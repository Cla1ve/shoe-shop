# Отчёт об отладке (ПР 2.11)

Чтобы потренироваться в отладке, я создал ветку `debug/exercise` и внёс в рабочий код три ошибки (коммит «Отладка: внёс три учебные ошибки»): одну в JavaScript, одну в Python и одну в логике. Потом искал их так, как будто не знаю, где они. Каждая найдена и исправлена отдельным коммитом.

Инструменты: `print` и логирование в Python (`logging` пишет трассировку ошибки в лог сервера), DevTools браузера (Network, Console, Sources), модульные тесты (`python3 -m unittest discover -s tests`).

## Ошибка 1. Каталог пустой, сервер отвечает 500 (Python)

**Как проявилась.** Страница открывается, но карточек нет.

**Как искал.**
1. DevTools, вкладка Network: запрос `products` красный, статус 500, ответ `{"error": "Внутренняя ошибка сервера"}` (`2.11_ошибка1_сеть_products_500_ответ.png`). `categories` при этом работает, значит, ошибка не в сервере в целом, а именно в каталоге.
2. Текст ошибки для пользователя общий, подробности сервер пишет в лог (`log.exception`). В логе трассировка (`2.11_ошибка1_лог_сервера_traceback.png`): `IndexError: No item with that key`, строка `total = row["total_qty"] or 0` в функции `product_dict`.

**Причина.** В запросе столбец называется `total_quantity`, а в функции я обратился к `total_qty`. Строка результата sqlite3 такого ключа не знает.

**Исправление.** `row["total_quantity"]`. Коммит «Исправил ошибку 1».

## Ошибка 2. Каталог всё равно не рисуется, ошибка в консоли (JavaScript)

**Как проявилась.** После исправления первой ошибки данные приходят (Network показывает 200), но на странице пусто.

**Как искал.**
1. DevTools, вкладка Console: `Uncaught (in promise) TypeError: Cannot read properties of null (reading 'firstChild')` и стек вызовов: `clear` → `renderCatalog` → `loadProducts` (`2.11_ошибка2_консоль_TypeError.png`).
2. Ссылка `app.js:37` в консоли открывает файл на вкладке Sources, на строке с `node.firstChild` стоит красный маркер (`2.11_ошибка2_источники_место_ошибки.png`). Значит, в `clear(node)` пришёл `null`, то есть элемент не найден. Вызов идёт из `renderCatalog`.

**Причина.** В `renderCatalog` я искал `$('#catalogue')`, а в `index.html` контейнер называется `catalog`. Функция `querySelector` вернула `null`.

**Исправление.** `$('#catalog')`. Коммит «Исправил ошибку 2».

## Ошибка 3. Не подсвечиваются товары с остатком ровно 3 пары (логика)

**Как проявилась.** Ошибок в консоли нет, страница выглядит нормально, но заметить, что часть товаров не подсвечена, можно только если знать данные: у четырёх моделей на складе ровно 3 пары.

**Как искал.** Запустил модульные тесты: упал `test_many_few_and_low_stock`, `AssertionError: False != True` на проверке `low_stock == (total_quantity <= 3)` (`2.11_ошибка3_тест_падает.png`). По тексту теста понятно, что для товара с остатком 3 сервер вернул `low_stock = False`.

**Причина.** В `product_dict` стоял оператор `<` вместо `<=`: `total < LOW_STOCK`.

**Исправление.** `total <= LOW_STOCK`. Коммит «Исправил ошибку 3». После этого все тесты проходят (`2.11_после_исправлений_тесты_проходят.png`).

## Проверка на устойчивость

Проверил, как приложение ведёт себя на неправильных данных (`2.11_устойчивость_неверные_данные.png`, `2.11_устойчивость_нет_файла_базы.png`):

| Ситуация | Что происходит |
|---|---|
| `id=abc` вместо числа | 400, «Нужен числовой параметр id» |
| несуществующий товар | 404, «Товар не найден» |
| тело запроса не JSON | 400, «Тело запроса должно быть корректным JSON» |
| поиск без результатов | пустой список, на странице «По вашему запросу ничего не найдено» |
| заказ без товаров | 400, «В заказе нет товаров» |
| заказ без входа | 401, «Сначала войдите в систему» |
| у товара нет файла картинки | в браузере показывается заглушка `picture.png` (`onerror`), каталог не ломается |
| нет файла `shop.db` | сервер не стартует и пишет, что нужно сначала запустить `create_db.py` и `import_data.py` |
| сервер не запущен | страница показывает уведомление «Нет связи с сервером» |

**Найдено при проверке.** Запрос `HEAD` на несуществующую картинку возвращал `501 Unsupported method`, потому что в сервере был реализован только GET и POST. Добавил `do_HEAD` и тест (`test_head_request`), теперь для HEAD приходят заголовки без тела, а для отсутствующего файла код 404.
